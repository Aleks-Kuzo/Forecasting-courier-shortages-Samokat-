# Прогнозирование дефицита курьеров в дарксторах

Решение Kaggle-соревнования (тестовое задание ecom.tech / Самокат): спрогнозировать **дефицит курьеров** (`target`) для каждого даркстора на неделю вперёд (24 ноября 2025 г.).

🏆 **WAPE = 0.1779 на лидерборде — 1 место**

Соревнование: `kaggle.com/competitions/intern-task-regression-courier-deficit-challenge`

## 🎯 Задача

Дефицит курьеров — это число курьеров, которое нужно дополнительно нанять, чтобы доставить все заказы без опозданий. Ноль означает, что даркстор укомплектован. Нужно по историческим данным (фактическая и прогнозная нагрузка, число курьеров, маркетинг и др.) предсказать дефицит на предстоящую неделю. Это задача регрессии, метрика — **WAPE**:

```
WAPE = sum(|y_true - y_pred|) / sum(|y_true|)
```

Так как WAPE = MAE · n / Σ|y|, модели обучаются на **MAE-лоссе**.

## 📊 Данные

Четыре источника, объединяются по ключам `calendar_dt` (понедельник недели) и `store_id`:

- **`facts.csv`**: факты за предыдущую неделю: нужное число курьеров, нагрузка, число доступных и вышедших на смены курьеров, процент опозданий, лайфтайм даркстора, город, отток курьеров, признак повышенного спроса, затраты на маркетинг.
- **`shifts_prediction.csv`**: прогноз на неделю вперёд: число заказов, нагрузка на курьера, нужное число курьеров.
- **`train.csv`**: целевая переменная `target` по датам и даркстора: 8 220 строк.
- **`test.csv`**: 2 438 дарксторов, для которых нужен прогноз на 24.11.2025.

Что важно знать про данные:

- **89% обучающей выборки** приходится на последние 3 недели: 3, 10 и 17 ноября 2025, более ранняя история очень скудная.
- Распределение таргета: среднее 2.4, максимум 31, **33% нулей**.

## 🔧 Пайплайн

1. **Объединение данных.** `train` и `test` склеиваются, затем подтягиваются признаки из `facts` и `shifts_prediction`.
2. **Обработка пропусков.**
   - Пропуски в `fact_couriers_with_shifts_lag_1`, `fact_load_factor_lag_1` и прогнозных признаках заполняются **медианой по даркстору**, а если данных по магазину нет, то общей медианой. Медианы считаются **только по историческим данным** (без тестовой недели).
   - `fact_percent_lateness_lag_1`: пропусков много, поэтому добавлен флаг `lateness_missing`, а сами пропуски заменены на `-1` (модель различает «опозданий не было» и «данных нет»).
   - Остальные пропуски (например, `marketing_costs_lag_1`) оставлены как есть: градиентный бустинг обрабатывает их нативно.
3. **Feature engineering: 31 признак (14 исходных + 17 созданных).**
   - Календарные: месяц, номер недели.
   - **Дельты** между прогнозом и фактом (абсолютные и относительные) по числу курьеров, заказов и нагрузке.
   - **Лаги на 2 недели** по заказам, штату, нагрузке и опозданиям.
   - **Скользящее среднее** (окно 3 недели) по тем же метрикам.
   - Все лаги и скользящие считаются по `lag_1`-колонкам внутри каждого даркстора, то есть **по значениям таргета признаки не строятся**.
4. **Валидация.** `KFold(n_splits=5, shuffle=True, random_state=42)`, расчёт **OOF-предсказаний** (каждая строка train предсказана моделью, которая её не видела). По OOF сравниваются модели и бленды.
5. **Модели.** LightGBM, CatBoost, XGBoost: все с MAE-лоссом и ранней остановкой. Предсказания на тесте усредняются по фолдам.
6. **Блендинг.** Итоговый ответ: среднее LightGBM и CatBoost.
7. **Постобработка.** `clip(0, None)` и округление до целого числа курьеров.

## 📈 Результаты

### Бейзлайны (5-fold CV, WAPE)

| Подход | WAPE |
|---|---|
| Глобальная медиана таргета | 0.8247 |
| Медиана таргета по даркстору | 0.6425 |
| Правило «прогноз штата − вышедшие на смены» | 0.9733 |
| LightGBM, сырые признаки | 0.1805 |
| XGBoost, сырые признаки | 0.1798 |
| CatBoost, сырые признаки | 0.1688 |

### Модели на инженерных признаках (OOF, 5-fold CV, WAPE)

| Модель | WAPE |
|---|---|
| LightGBM | 0.1694 |
| XGBoost | 0.1717 |
| CatBoost | 0.1712 |
| LightGBM + XGBoost | 0.1697 |
| **LightGBM + CatBoost** | **0.1677** |

**Итоговое решение:** бленд LightGBM + CatBoost. CV WAPE = 0.1677, лидерборд WAPE = 0.1779 (**в 3.8 раза точнее** лучшего простого бейзлайна, медианы по магазину).

### Гиперпараметры

| Модель | Параметры |
|---|---|
| LightGBM | `n_estimators=1500`, `learning_rate=0.03`, `num_leaves=22`, `max_depth=5`, early stopping 100 |
| CatBoost | `iterations=3000`, `learning_rate=0.03`, `depth=6`, `rsm=0.8`, early stopping 100 |
| XGBoost | `n_estimators=3000`, `learning_rate=0.03`, `max_depth=6`, `min_child_weight=7`, `subsample=0.8`, `colsample_bytree=0.7`, `reg_lambda=5`, early stopping 100 |

## 🔍 Выводы и решения

- **Почему обычный KFold, а не `TimeSeriesSplit`.** Из-за того, что почти вся выборка сосредоточена в последних неделях, временной сплит оставил бы модели примерно на треть меньше данных для обучения. Усреднение предсказаний по фолдам смягчает переобучение под конкретные недели.
- **Признаки по таргету не использовались.** Лаги и скользящее среднее по `target` улучшали локальную метрику, но ухудшали результат на лидерборде, поэтому от них отказался (код оставлен закомментированным в ноутбуке).
- **Эффект признаков неоднозначен.** Для LightGBM он заметный (0.1805 → 0.1694), а CatBoost на сырых признаках оказался не хуже (0.1688 против 0.1712 на инженерных). Основной выигрыш в итоге дал бленд.
- **Высокая корреляция признаков** не проблема: деревья устойчивы к мультиколлинеарности.

⚠️ **Ограничения.** CV немного оптимистичен: фолд валидации используется для ранней остановки, а разбиение случайное, а не по времени. Разница между CV (0.1677) и лидербордом (0.1779) это подтверждает.
